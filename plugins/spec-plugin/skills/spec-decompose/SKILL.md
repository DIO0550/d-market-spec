# Spec Decompose

`.plugin-workspace/.specs/{nnn}-{feature-name}/` の implementation-plan / tasks を、**コンテキストの小さいローカルLLM（OpenCode 等）が1タスクずつ実行できる粒度**のマイクロタスクに分割するスキル。

このスキル自体はコードを実装しない（分割ファイルの生成のみ。`.plugin-workspace/.specs/` 内にしか書かないため、計画フェーズ中でも実行できる）。

## 設計原則

ローカルLLMは「計画全体を読んで文脈を補う」ことができない。したがって:

1. **自己完結** — 各マイクロタスクファイルは、implementation-plan や他のタスクファイルを読まずに単体で実行できる。必要な既存コードは抜粋を**ファイル内に引用**する
2. **小粒度** — 1マイクロタスク = 1ファイル以下の変更、diff 目安 100 行以内。「複数ファイルにまたがる判断」が必要なら、その判断はこのスキル（分割時）が済ませ、マイクロタスクには結果だけ書く
3. **小サイズ** — 1ファイルはおおよそ 150 行以内に収める。超える場合はタスクをさらに割る
4. **検証可能** — 各マイクロタスクは完了条件として実行可能なコマンド（またはコンパイル・目視手順）を持つ

## Step 1: specフォルダの特定

```bash
# 番号指定時
spec_dir=$(ls -1d .plugin-workspace/.specs/$0-* 2>/dev/null | head -1)
# 番号省略時（archive外で最大番号を自動選択）
spec_dir=$(ls -1d .plugin-workspace/.specs/[0-9][0-9][0-9]-* 2>/dev/null | sort -rn | head -1)
```

見つからない場合はエラーを報告して終了。自動選択した場合はフォルダ名を表示する。

## Step 2: 計画の読み込み

`{dir}/implementation-plan.md` と `{dir}/tasks.md` を Read する。

- `[NEW]` / `[MODIFY]` / `[DELETE]` の変更エントリとコード骨格を把握する
- tasks.md の Implementation / Verification セクションのタスクを分割対象とする（Research & Planning は計画時に完了済みのため対象外）
- tasks.md に `■`（完了済み）のタスクがある場合、そのタスクは分割対象から除外する

## Step 3: 分割方針の決定

tasks.md の各タスクを 1..N 個のマイクロタスクに割る。分割の目安:

- `[NEW]` エントリ → 「型・定数定義」「主要ロジック」「エクスポート・接続」のように、コンパイル可能な断面で割る
- `[MODIFY]` エントリ → before/after の差分単位で割る（1箇所の変更 = 1マイクロタスク）
- テストタスク → テスト対象の関数・ケース群単位で割る
- 依存関係は**直列の実行順**に落とす（ローカルLLMに並列判断をさせない）。順番どおり実行すれば常にコンパイルが通る順序にする

## Step 4: 既存コード抜粋の収集

`[MODIFY]` 対象と、マイクロタスクが参照する既存の型・関数・規約について、**該当箇所だけ** Read（offset/limit 指定）し、抜粋をマイクロタスクに引用できるよう控える。

- 抜粋は「そのタスクの実装に必要な最小限」（シグネチャ・該当ブロック程度）。ファイル全文は引用しない
- 引用には `file:line` を付ける（ローカルLLM側が Read し直せるように）

## Step 5: マイクロタスクファイルの生成

`{dir}/local-tasks/` を作成し、テンプレート `assets/templates/micro-task.md` に沿って `{NN}-{slug}.md` を実行順の連番で生成する。

守ること:

- テンプレートの全セクションを埋める。**プレースホルダ `{...}` を残さない**
- 「実装内容」のコード骨格は implementation-plan から該当部分を**転記**する（要約しない。`...` や「省略」で端折らない）
- 「このタスクでやらないこと」に、隣接タスクとの境界（触ってはいけないファイル・後続タスクに回す部分）を明記する — 小さいモデルのスコープ逸脱を防ぐ最重要セクション

## Step 6: INDEX の生成

テンプレート `assets/templates/INDEX.md` に沿って `{dir}/local-tasks/INDEX.md` を生成する。

- 全マイクロタスクの実行順リスト（`□` / `■` で進捗管理）
- 各行に対応する tasks.md のタスクを併記（tasks.md 側は親、INDEX 側が子の関係。子が全部 `■` になったら tasks.md の親タスクを `■` にする）

## Step 7: 完了報告

以下を報告する:

1. 生成したマイクロタスク数と `local-tasks/` のパス
2. 使い方の案内:
   - OpenCode / ローカルLLM には **INDEX.md の順に1ファイルずつ** 渡す（例: 「`local-tasks/01-xxx.md` を読んで、その内容だけを実装して」）
   - 1タスク完了ごとに完了条件を実行し、通ったら INDEX.md の `□` を `■` に更新してから次へ進む
   - 全タスク完了後の PLANNING / ガード削除・DoD 照合は `/spec-implement` または `/spec-implement-exp` の Step に従う（本スキルは分割のみ）
