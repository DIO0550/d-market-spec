# テストレビュー指摘分類ルール

テストコード品質レビューにおける指摘の分類基準。全エージェント共通で適用する。

---

## 分類一覧

| 分類 | 意味 | アクション | アイコン |
|------|------|-----------|---------|
| CRITICAL | ルール違反 | 必ず修正 | 🔴 |
| WARNING | 要確認の潜在的問題 | 基本修正 | 🟡 |
| INFO | 参考情報 | 任意対応 | 🔵 |
| PROTECTED | 仕様が正当化するテストパターン | **現状維持推奨** | 🟢 |

---

## CRITICAL: ルール違反

### 定義

テストレビュールールに明確に違反しているコード。修正が必要。

### 該当条件

- 内部モジュールをモックしている（MOCK-SCOPE 違反）
- 内部コラボレーターへの spy アサーション（BEHAVIOR-TEST 違反）
- プライベートメソッドの直接テスト（BEHAVIOR-TEST 違反）

### 出力フォーマット

```markdown
### C-{NNN}: {タイトル}

- **次元**: {担当次元名}
- **対象**: `{ファイルパス}` L{行番号}
- **仕様根拠**: {spec文書名 Section X: "引用"}
- **コード**: {違反箇所のコードスニペット}
- **問題**: {問題の説明}
- **修正案**: {具体的な修正提案}
```

---

## WARNING: 要確認

### 定義

ルール違反の可能性があるが、コンテキストによって判断が分かれる境界ケース。

### 該当条件

- 内部インターフェースが外部依存をラップしている場合のモック（MOCK-SCOPE 境界）
- 中間データ形状のアサーション（BEHAVIOR-TEST 境界）
- テストファイルの配置が既存規約と異なる

### 出力フォーマット

```markdown
### W-{NNN}: {タイトル}

- **次元**: {担当次元名}
- **対象**: `{ファイルパス}` L{行番号}
- **仕様根拠**: {spec文書名 Section X: "引用"}
- **コード**: {該当箇所のコードスニペット}
- **問題**: {問題の説明}
- **改善案**: {具体的な修正提案}
```

---

## INFO: 参考情報

### 定義

問題ではないが、将来の保守やテスト改善の参考になる観察事項。

### 該当条件

- テストパターンの改善提案
- テストカバレッジの拡張ポイント

### 出力フォーマット

```markdown
### I-{NNN}: {タイトル}

- **対象**: `{ファイルパス}` L{行番号}
- **観察**: {観察内容}
```

---

## PROTECTED: 仕様が正当化するテストパターン

### 定義

表面的にはルール違反に見えるが、計画ドキュメントに明確な根拠があり、現状維持が推奨されるテストコード。

### 該当条件

- implementation-plan のテスト戦略で指定されたモック戦略に従ったモック使用
- exploration-report のテストインフラ規約に合わせたパターン
- implementation-plan で明示的に指定されたテスト方針に基づくアサーション
- hearing-notes の要件に基づく個別テストケース

### PROTECTED 優先ルール

ルール違反に見えるが仕様根拠がある場合、**PROTECTED が優先**する。仕様に根拠がある限り、保護を優先する。

### 出力フォーマット

```markdown
### P-{NNN}: {タイトル}

- **次元**: {担当次元名}
- **対象**: `{ファイルパス}` L{行番号}
- **表面的な印象**: {ナイーブなレビューアーが言いそうなこと}
- **仕様による正当化**: {spec文書名 Section X: "引用"}
- **結論**: 現状維持を推奨
```

---

## 指摘番号の採番ルール

各エージェントは自分の出力内で独立に番号を振る:

- `C-001`, `C-002`, ... (CRITICAL)
- `W-001`, `W-002`, ... (WARNING)
- `I-001`, `I-002`, ... (INFO)
- `P-001`, `P-002`, ... (PROTECTED)

オーケストレーターが統合レポートを生成する際に、全エージェントの指摘を通し番号で再採番する。

---

## 無効な指摘パターン

以下のような指摘は、仕様ドキュメントに根拠がない限り出してはならない。

| 無効な指摘 | 必要な仕様根拠 |
|-----------|--------------|
| 「このモックは不要です」 | テスト戦略でこのモックが不要とされているか？ |
| 「テストが多すぎます」 | テストTODOリストのどの項目が不要か？ |
| 「このテストパターンは非推奨です」 | exploration-report のテストインフラ規約でどう定められているか？ |

**すべての指摘には「仕様根拠」フィールドを必須で含める。** 引用できない指摘は PROTECTED に分類するか、除外する。
