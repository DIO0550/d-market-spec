# テストレビュー指摘分類ルール

テストコード品質レビューにおける指摘の分類基準。

---

## 分類一覧

| 分類 | 意味 | アクション | アイコン |
|------|------|-----------|---------|
| VIOLATION | ルール違反 | 必ず修正 | 🔴 |
| WARNING | 要判断（境界ケース） | コンテキストに応じて対応 | 🟡 |
| OK | 問題なし | — | ✅ |

---

## VIOLATION: ルール違反

### 定義

テストレビュールールに明確に違反しているコード。修正が必要。

### 出力フォーマット

```markdown
### V-{NNN}: {タイトル}

- **ルール**: {ルールID — MOCK-SCOPE / BEHAVIOR-TEST}
- **対象**: `{ファイルパス}` L{行番号}
- **コード**: {違反箇所のコードスニペット}
- **問題**: {問題の説明}
- **修正案**: {具体的な修正提案}
```

---

## WARNING: 要判断

### 定義

コンテキストによってルール違反かどうかが変わる境界ケース。レビュイーの判断が必要。

### 出力フォーマット

```markdown
### W-{NNN}: {タイトル}

- **ルール**: {ルールID}
- **対象**: `{ファイルパス}` L{行番号}
- **コード**: {該当箇所のコードスニペット}
- **状況**: {なぜ境界ケースなのかの説明}
- **判断基準**: {どう判断すべきかのガイダンス}
```

---

## OK: 問題なし

サマリーで使用。レビュー対象ファイル・テスト関数のうち、全ルールに適合しているものをカウントする。個別の出力フォーマットはなし。

---

## 指摘番号の採番ルール

- `V-001`, `V-002`, ... (VIOLATION)
- `W-001`, `W-002`, ... (WARNING)

ルール横断で通し番号を振る（ルール別ではない）。
